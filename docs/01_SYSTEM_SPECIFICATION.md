# 01 — System Specification (Baseline จาก Source Code)

> เอกสารนี้สรุปสิ่งที่อ่านพบใน Source Code ปัจจุบัน ไม่ใช่ข้อกำหนดใหม่ที่ได้รับการอนุมัติทั้งหมด หากรายละเอียดใดไม่ชัดเจนให้ระบุว่า Pending Verification แทนการคาดเดา

## 1. Source Inventory

- ไฟล์หลัก: `index (1).html`
- ขนาดที่ตรวจพบใน Git: 1,226,361 bytes
- ประกอบด้วย HTML, CSS และ JavaScript ภายในไฟล์เดียว
- จากการตรวจรอบก่อน: พบ 6 script tags และ 1 style block
- ไม่พบการเรียก fetch/XHR ในไฟล์ที่ตรวจ ณ เวลานั้น
- การไม่พบ fetch/XHR ในไฟล์นี้ไม่ได้พิสูจน์ว่าไม่มีบริการภายนอกหรือ Backend ในระบบทั้งหมด

## 2. ส่วนติดต่อผู้ใช้

พบแท็บหลัก 4 ส่วน:

- ดวงบุคคล
- เทพประจำตัว
- โอเรกุรัม
- ไพ่ทาโรต์และรูน

ฟอร์มข้อมูลส่วนบุคคลใช้โครงสร้าง sharedForm ร่วมกันระหว่างแท็บตามที่ตรวจพบ

## 3. การจัดเก็บข้อมูลฝั่ง Browser

- Local Storage key ที่ตรวจพบ: `horakratai_form_state_v1`
- มีการบันทึกค่าจากเหตุการณ์ input/change
- มีการกู้คืนค่าระหว่างโหลดหน้า
- มีการใช้ MutationObserver

ต้องทดสอบจริงเพิ่มเติมเรื่องวงจรชีวิตของข้อมูล การล้างข้อมูล ความเข้ากันได้เมื่อเปลี่ยน schema และผลกระทบด้านความเป็นส่วนตัว

## 4. สูตรและโมดูลคำนวณที่ตรวจพบ

### 4.1 เลขศาสตร์และพื้นดวง

- มีชุดเลขศาสตร์ไทยและอังกฤษ: `THAI_CHAR`, `ENG_PYTHAGOREAN`
- ฟังก์ชันลดเลขหลัก: `reduce1` ให้ผลในช่วง 1–9
- ค่า N คือเลขศาสตร์ชื่อและนามสกุล โดยนำช่องว่างออกก่อนคำนวณ
- R1 = reduce1(วัน + เดือน + ปี + N)
- J = reduce1(ชั่วโมง + นาที) เมื่อทราบเวลาเกิด; หากไม่ทราบเวลา J = 0
- BaseCode = reduce1(R1 + J)

### 4.2 ลัคนา

- Source ใช้ราศีอาทิตย์จากวัน/เดือนเกิดร่วมกับช่วงเวลาเกิดทุก 2 ชั่วโมง โดยเริ่มที่ 06:00
- เมื่อไม่ทราบเวลาเกิด ฟังก์ชันคำนวณลัคนาจะถูกปิดตามเงื่อนไขที่ตรวจพบ
- ไม่พบการใช้พิกัดสถานที่เกิดหรือ astronomical ephemeris ในอัลกอริทึมที่ตรวจ
- จึงต้องอธิบายว่าเป็นอัลกอริทึมเฉพาะของระบบ ไม่ใช่การคำนวณลัคนาดาราศาสตร์เต็มรูปแบบ

### 4.3 RHD

- มีคู่ Rabbit 1–9 × Habit 1–9 รวม 81 คู่
- ฟังก์ชันที่เกี่ยวข้อง: `rhdSynthesis()`, `buildRHDMatrix()`

### 4.4 เทพประจำตัว

- ผลรวมเลขศาสตร์ชื่อ + วันเดือนปีเกิด + เวลาเกิด (ถ้ามี) แล้วลดเหลือ 1–9
- หากไม่ทราบเวลาเกิด จะไม่รวมเวลา

### 4.5 โอเรกุรัม

- Source มีคำถาม 100 ข้อ หมายเลข 1–100
- มีชุดข้อมูลคำอธิบายหลายระดับ เช่น `OREGU_DEEP`, `OREGU_EXTRA_DEEP`, `OREGU_EASY`
- มีการคูณตัวคูณตามลำดับข้อ: ข้อ 1–20 ×2, 21–40 ×4, 41 ขึ้นไป ×6 แล้วลดเลขเป็น R4
- สูตรโอเรกุรัมเป็นคนละชุดกับ `topicCodeOf()` ห้ามนำสองสูตรมาปะปนกัน
- ต้องตรวจรายละเอียดการรวมค่าตัวแปรและการเลือกข้อความจาก Source ก่อนแก้สูตร

### 4.6 ไพ่ รูน และคริสตัล

- Major Arcana 21 ใบ ใช้ modulo 21
- Minor Arcana 56 ใบ (4 suits × 14) ใช้ modulo 56
- Rune 24 ตัว
- ไพ่ส่วนบุคคล/ไพ่เหตุการณ์/รูนประจำวัน/คริสตัลส่วนบุคคลและประจำวันมีฟังก์ชันคำนวณแยกกัน
- ไม่มี The Fool ในชุด Major 21 ใบตามข้อมูลที่ตรวจพบ; ต้องถือเป็นลักษณะปัจจุบัน ไม่ใช่ข้อผิดพลาด เว้นแต่มีข้อกำหนดให้เปลี่ยน

## 5. ระบบคำทำนายและข้อมูล

ชุดข้อมูลที่ตรวจพบประกอบด้วย:

- `RABBITS`
- `ELEMENTS`
- `RHD_HABITS`
- `GOD_DATA`
- `GOD_RITUAL`
- `BASE_DEEP`
- `ASC_DEEP`
- `TOPIC_PRED`
- `PRED_DEEP`
- `SPECIFIC_PREDICTIONS_DETAILED`
- `OREGU_DEEP`
- `OREGU_EXTRA_DEEP`
- `OREGU_EASY`

หมวดคำทำนายที่ตรวจพบ: การงาน การเงิน สุขภาพ ความรัก เรื่องที่สนใจ และเรื่องอื่น ๆ

### 5.1 ช่วงเวลาคำทำนาย

- คำทำนายราย 7 วันเริ่มจากวันถัดไป และใช้เวลา 12:00 ในการคำนวณตาม Source ที่ตรวจ
- คำทำนายราย 3 เดือนเริ่มจากเดือนถัดไปและคำนวณต่อเนื่องด้วยเลขเดือน
- Daily element ใช้เวลาจริง ขณะที่ราย 7 วันใช้เวลา 12:00 จึงอาจให้ผลต่างกัน
- วันพุธอาจมีเงื่อนไขแบ่งช่วงก่อน/หลัง 18:00

### 5.2 กลุ่มผลโอเรกุรัม

ค่าที่ตรวจพบใน `OREGU_BUCKET`:

- good = 1, 3, 9
- mid = 2, 5, 6, 8
- warn = 4, 7

## 6. Validation ที่ตรวจพบ

- `isSharedComplete()` ตรวจว่าชื่อ/นามสกุล/วัน/เดือน/ปีมีค่า แต่ไม่ได้ตรวจความถูกต้องของวันที่
- `renderTarotRuneStandaloneResult()` มีการตรวจวันเกิดจริงและช่วงเวลา 00:00–23:59
- เงื่อนไข Validation ไม่เหมือนกันทุกโมดูล ต้องรวมเป็นข้อกำหนดกลางหลังจากสำรวจทุกเส้นทาง

## 7. ข้อกำหนดก่อนแก้ไข

ก่อนแก้สูตรหรือข้อมูลคำทำนาย ต้องบันทึก:
1. ฟังก์ชัน/ชุดข้อมูลเดิม
2. ตัวอย่าง input และ output ปัจจุบัน
3. พฤติกรรมที่ต้องการเปลี่ยนและเหตุผล
4. ผลกระทบต่อโมดูลอื่น
5. Regression cases ที่ต้องผ่าน

## 8. รายการ Pending Verification

- รายละเอียดสูตรโอเรกุรัมครบทุกตัวแปร
- กฎเลือกคำทำนายของทุกหมวดและทุกช่วงเวลา
- ขอบเขตวันเกิด/ปีปฏิทินและการรองรับปี พ.ศ./ค.ศ.
- Validation ของทุกโมดูล
- พฤติกรรม Local Storage เมื่อข้อมูลไม่ครบหรือ schema เปลี่ยน
- การทำงานจริงของ MutationObserver
- การแสดงผลบน Browser/มือถือ/แท็บเล็ต
