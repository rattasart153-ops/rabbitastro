## 3. ผลตรวจรอบที่ 2 — Verification จาก Source

### ตัวอย่างข้อมูลทดสอบที่ใช้

ข้อมูลสมมติ: ชื่อ Nobi, นามสกุลว่างในตัวอย่าง, วันเกิด 1 มกราคม 1990, ไม่ทราบเวลาเกิด  
วันที่อ้างอิง: 4 พฤศจิกายน 2026 เวลา 12:00  
โอเรกุรัม: ข้อ 1

ผลตัวอย่างที่บันทึกไว้จากการคำนวณตาม Source:
- เลขชื่อ Nobi: 22 → N = 4
- R1 = 1996 → 7
- J = 0
- BaseCode = 7
- เลขเทพประจำตัว = 7
- ไพ่ Major = The Moon
- ไพ่ Minor = Seven of Cups
- Daily Rune = Fehu
- Personal Crystal = Amethyst
- Daily Crystal = Tiger's Eye

> ตัวอย่างนี้เป็นการตรวจความสอดคล้องกับสูตรจาก Source ไม่ใช่การยืนยันผลจาก Runtime และไม่ใช่การรับรองความถูกต้องเชิงศาสตร์

### ข้อค้นพบเพิ่มเติม

- `NINE_STEP_MODE = 'lucky'`; ในโหมดนี้ `applyNineStep()` คืนค่าตัวเลขเดิมก่อน reduce ไม่ได้คูณ 9
- หากเกิดวันพุธและไม่ทราบเวลา `birthDayPower()` คืนค่า power 0
- `calcAscFeature()` ปิดการคำนวณลัคนาเมื่อไม่ทราบเวลาเกิด
- `topicCodeOf()` มีสูตร R1/R2/R3/J/N และ R4 ของตัวเอง ซึ่งไม่ควรสับสนกับสูตรโอเรกุรัม
- รูนส่วนบุคคลคำนวณจากชั่วโมง+นาทีเมื่อทราบเวลาเกิด
- dailyRune คำนวณจาก birthSum + dateSum
- `isSharedComplete()` ไม่ตรวจความถูกต้องจริงของวันที่ ขณะที่การแสดงผลไพ่/รูนแบบ standalone มี validation เพิ่มเติม
- ราย 7 วันใช้เวลา 12:00 ขณะที่ daily element ใช้เวลาจริง
