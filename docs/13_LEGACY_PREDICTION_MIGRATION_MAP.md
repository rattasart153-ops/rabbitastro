Branch: `test-matrix-of-destiny-rhd` only  
Status: Engine 1 content has been copied into unpublished JSON drafts; Engines 2–4 have not been migrated in this pass.

## Non-negotiable migration rules

1. Keep all calculation functions, arithmetic, input normalization, date/time handling, and result-code generation in the existing JavaScript engine.
2. Move only editable interpretation/content data into the JSON repository.
3. Preserve every legacy key and lookup path through an adapter. Do not rename categories, question IDs, feature keys, or result numbers during the first migration.
4. Keep original content as the source of truth until parity tests pass. No deletion of legacy constants during extraction.
5. Runtime content must be published before it can replace the matching legacy content. Missing JSON records must fall back to the existing JS data.
6. Never write to `main`, `Admin`, or Production as part of this work.

## Record identity convention

Use stable IDs that preserve legacy lookup identity, for example:

- `engine1:topic:work:result:1`
- `engine1:prediction:rabbit:1`
- `engine1:prediction:ascendant:aries`
- `engine1:rhd:habit:1`
- `engine2:deity:1`
- `engine3:question:<legacy-question-id>`
- `engine3:prediction:<category>:<result-number>`
- `engine4:tarot:major:1`
- `engine4:rune:fehu`
- `engine4:crystal:1`

The exact IDs must be confirmed against every legacy lookup before import. Do not create duplicate IDs or silently normalize legacy keys.
